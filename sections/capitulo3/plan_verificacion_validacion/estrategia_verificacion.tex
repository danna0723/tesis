La estrategia de verificación del sistema Thary consiste en la realización de pruebas mediante el uso de \textit{pytest}. Las pruebas se realizan sobre aquellos componentes del sistema que, de fallar, podrían comprometer la calidad y confiabilidad de las predicciones de los productos o la funcionalidad general del sistema. Las pruebas se implementaron en el directorio \texttt{tests} en 5 archivos diferentes, cada uno enfocado en verificar el correcto funcionamiento de uno de los componentes del sistema:

\begin{itemize}
    \item \texttt{test\_carga\_datos.py}: En esta prueba se verifica que el sistema permita a los usuarios cargar archivos CSV de forma correcta. Se verifica que el sistema no se rompa al recibir archivos con datos de entrada incorrectos, incompletos o faltantes. De existir alguno de estos errores, el sistema debe mostrar un mensaje de error al usuario para cada caso en el que se le indique de forma clara qué errores son los que tiene el CSV y qué debe corregir antes de cargarlo nuevamente. Por último, en esta prueba también se verifica que el sistema cumpla con el RNF-02 y que sea capaz de reconocer columnas heterogéneas, tanto en español como en inglés, y procesarlas correctamente.

    \item \texttt{test\_combinacion.py}: En esta prueba se verifica que el peso que se usa para combinar los resultados de los modelos XGBoost y Media Móvil sea calculado correctamente. También se comprueba que no haya errores en casos como aquel en el que las dos predicciones combinadas son idénticas.

    \item \texttt{test\_modelos.py}: En esta prueba se verifica que la lógica de selección del mejor modelo por producto funcione correctamente. Para esto se comprueba el cálculo de errores, la selección del modelo y la validación mediante la prueba de Diebold-Mariano con la corrección de Harvey-Leybourne-Newbold.

    \item \texttt{test\_pronostico\_futuro.py}: En esta prueba se verifica el cálculo del rango de predicción y la identificación de casos de baja confianza, incluyendo los casos en los que el límite inferior del rango se recorta a cero.

    \item \texttt{test\_reposicion.py}: Durante esta prueba se verifica que los cálculos de stock de seguridad, punto de reorden, EOQ, presupuesto, costos y alertas de reposición se realicen correctamente para posteriormente ser mostrados al usuario en la interfaz.
\end{itemize}

Para los cálculos que tienen una única respuesta correcta (\texttt{test\_reposicion.py}, \texttt{test\_combinacion.py} y \texttt{test\_modelos.py}), se aplica un enfoque llamado \textit{oráculo conocido}, el cual consiste en, antes de hacer una prueba, calcular manualmente con base en la fórmula correspondiente cuál es el resultado correcto que el sistema debería dar, y después verificar si el sistema entregó o no dicho resultado.

En total, la suite de pruebas está compuesta por 60 pruebas automatizadas. Estas pruebas se ejecutan mediante \textit{pytest} y permiten verificar diferentes partes de la lógica del sistema de forma independiente.
